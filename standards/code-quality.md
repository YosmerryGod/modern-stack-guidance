# Code Quality Standard

- Prefer clear names, cohesive functions, and abstractions proportional to the problem.
- Avoid duplicated business rules without creating generic frameworks for one-off code.
- Handle errors at boundaries and preserve useful context.
- Follow project conventions unless unsafe or materially obstructive.
- Keep configuration explicit and document non-obvious operational decisions.
- Keep diffs focused; avoid unrelated formatting churn.
- Preserve compatibility unless a breaking change is requested.
- Include tests or explain why they are not practical.
- Update documentation when behavior, configuration, or operations change.
